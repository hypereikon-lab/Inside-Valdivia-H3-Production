# MiniMax H3 Fun Control characterization matrix

This directory contains 34 independent API graphs generated by
`tools/build_fun_control_batch.py`. They are an empirical comparison surface,
not promoted production workflows.

## Fixed experimental basis

- source: frames `[0, 73)` of `Gen-4_5.gen-4_5 (5).mp4`;
- generation: `768 × 768`, 73 frames, 24 fps;
- seed: `20260902`;
- scheduler: `simple`;
- sampler: `res_multistep`;
- quality profile: 20 steps, denoise 1.0;
- FL2VA/Ref2VA trunks: pruned INT8 ConvRot weights;
- control patch: MiniMax H3 Fun ControlNet Union pruned INT8 ConvRot;
- no audio conditioning, generated audio, training, streaming, or auxiliary
  enhancement model.

The already executed strength-1 Canny and DA3-depth graphs remain the fixed
baselines and are referenced from `matrix.json`; the batch does not spend GPU
time duplicating them.

## Axes

| Family | Question isolated |
|---|---|
| `strength` | How does scalar Fun Control strength change adherence and image freedom? |
| `diffusion-window` | What changes when the patch acts early, late, or in the middle of denoising? |
| `carrier` | How do Canny density and DA3 depth differ at fixed generation state? |
| `temporal-envelope` | Can control-map intensity be ramped or pulsed over video time before H3 encodes it? |
| `carrier-interpolation` | What happens when the input control video continuously crossfades between depth and Canny? |
| `reference-control` | How does native Ref2VA image conditioning compose with the native Fun Control patch? |
| `reference-fidelity` | Is Ref2VA `max` worth its higher token and runtime cost relative to `match`? |
| `endpoint-control` | How do FL2VA first/last frames constrain the same control trajectory? |
| `guide-control` | How does an interior native `MiniMaxH3AddGuide` anchor compose with control? |
| `reference-guide-control` | Can reference identity, an interior guide, and control coexist without a reset? |
| `inpaint` | What does native Fun temporal or spatial regeneration do from the source video alone? |
| `inpaint-control` | Does Canny stabilize masked regeneration? |
| `reference-inpaint-control` | Can reference appearance, temporal regeneration, and structural control be composed? |

## Semantic cautions

- `start_percent` and `end_percent` address diffusion progress, not video time.
- The current upstream H3 Fun implementation thresholds the regeneration mask
  at `> 0.5`; the temporal and spatial inpaint masks in this matrix are binary.
- The temporal envelope experiments are different: their continuous masks are
  applied to the control-map pixels before H3 VAE encoding, so they genuinely
  create time-varying control-video intensity.
- A depth/Canny crossfade is an input-carrier experiment. It does not claim that
  the model internally interpolates two separately typed control modalities.
- Queue completion proves only that a graph executed. SSIM, hashes, geometry,
  and adjacent-frame luma change are bounded descriptors. Motion quality,
  reference use, spatial coherence, and usefulness require human review.

## Durable HTTP execution

`batch-plan.json` uses `comfy.run-batch/1`. Runtime Control validates all 34
graphs against one fresh live `/object_info` before the first submission,
serializes GPU load, persists every exact prompt id before polling, and can
resume after transport loss without duplicate generation. Independent terminal
failures receive `blocked` receipts while later tests continue.

Cloudflare service-token values are retrieved from macOS Keychain and passed
only in the runner process environment. Browser cookies and visual UI state are
not part of this protocol.

All 34 graphs completed without a terminal job failure. Their prompt ids,
receipts, output hashes, geometry and bounded decoded metrics are retained in
`runtime/characterizations/2026-09-02-h3-fun-control-matrix.json`. This changes
the matrix state from planned to `executed-pending-human-review`; it does not
promote any strength, diffusion window, carrier, reference, guide or inpaint
combination.

## Review artifacts

After execution, `tools/analyze_fun_control_batch.py` writes a JSON/Markdown
technical index and family-level comparison videos. Every generated video is
downloaded together with the exact control-video or mask preview that produced
it. The comparison folder is a review aid, not another application layer.
